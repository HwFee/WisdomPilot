# Bug 记录：注册接口邮箱格式错误漏出原始英文（2026-08-01，已修复）

## 状态

**已修复**（2026-08-01）。修复后实测：

```
邮箱无@        -> 422 {"detail": "请输入有效的邮箱地址"}
邮箱 a@b      -> 422 {"detail": "请输入有效的邮箱地址"}
用户名/密码弱  -> 422 {"detail": "用户名: 用户名至少需要2个字符; 密码: 密码长度至少需要8个字符"}
```

回归：`backend/tests/test_auth.py` 20 passed、全量 `pytest tests/` 286 passed。

## 修复内容

`backend/app/core/exceptions.py`：

- 删除失效分支 `if error_type == "value_error.email": return "请输入有效的邮箱地址"`（V1 老格式，V2 永不命中）；
- 新增 `if error_type == "value_error" and "valid email address" in message: return "请输入有效的邮箱地址"`。
  用**消息模板内容**识别邮箱错误（EmailStr 两条路径的消息都是 `value is not a valid email address: {reason}`），
  而非 `ctx` 键名——起初用 `"reason" in context` 判定，复核后发现它只是「当前依赖恰好只有 EmailStr
  用 reason 键」，其它 `PydanticCustomError` 也可带 `reason`，存在误判风险，故改为匹配消息内容；
- 同步更新 `format_validation_error` docstring。

## 现象

`POST /api/auth/register` 邮箱格式非法时，返回：

```json
{"detail": "邮箱: value is not a valid email address: An email address must have an @-sign."}
```

原始英文 Pydantic 消息直接透传给前端，未转为中文。

## 位置

- `backend/app/core/exceptions.py:123`（`format_validation_error` 中的 `value_error.email` 分支）
- 兜底路径 `backend/app/core/exceptions.py:86-88`（`format_value_error`）

## 前端拦截情况（2026-08-01 复核）

注册页邮箱输入框是 `type="email"` + `required`（`frontend/app/register/page-client.tsx:130`），
浏览器原生 HTML5 邮箱校验会在提交前拦截掉明显非法的输入（如 `not-an-email`），
所以**正常 UI 流程中用户看不到后端英文消息**。

但前端拦截不是完整的，漏洞依然可达：

1. HTML5 的邮箱校验是宽松的，`a@b` 能通过浏览器（正则只需 `xxx@xxx`），
   而后端 `email-validator` 判不合法，实测返回：
   `value is not a valid email address: The part after the @-sign is not valid. It should have a period.`
2. 直接调 API（curl / 其他客户端）绕过前端，必现原始英文。

结论：前端 `type="email"` 只是「常见误输」的兜底，不是格式契约的保证；
**422 响应 `detail` 的文案依然是后端契约问题**，属于真实缺陷。

## 根因

Pydantic v2 对 `EmailStr` 校验失败产生的错误 `type` 是 `value_error`（`ctx` 为 `{"reason": "..."}`），
**不是** `value_error.email`。代码里 `error_type == "value_error.email"` 的分支（期望返回
「请输入有效的邮箱地址」）永远不命中，错误掉进 `format_value_error` 的通用路径——那里只剥
`"Value error, "` 前缀，英文原句（`value is not a valid email address: ...`）就漏了出来。

对照：用户名/密码的 `ValueError` 能正确转中文（`ctx` 含 `error` 字段，走 `exceptions.py:75-76`
分支），所以只有邮箱格式这一个场景受影响。

## 复现

```
POST /api/auth/register
{"email": "not-an-email", "username": "abc", "password": "abc12345"}
→ 422 {"detail": "邮箱: value is not a valid email address: An email address must have an @-sign."}
```
