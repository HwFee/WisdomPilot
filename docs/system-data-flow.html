这张图在说什么

用户在四个模块里做练习 → 每次练习会产生「掌握度事件」写入事件表 → HLR 模型重放事件算出每个知识点的回忆概率(p_l)和等级 → 缓存起来 → 仪表盘/能力图谱/复盘页读取这些数据给用户看。

✅ 代码审查室、费曼检验、定级测试：会写掌握度事件，数据流是通的。

❌ 调试竞技场：完全不写掌握度事件。用户在竞技场练了再多，知识点掌握度也不会变。调试轴的4个知识点只有定级测试写过一次初始值，之后永远停滞。

⚠️ 认证考试：除了定级测试，正式认证也不写掌握度事件，只写认证记录和经验值。

理想流程

注册 → 定级测试冷启动 → 日常练习积累掌握度 → 弱点浮现 → 针对性补弱 → 认证验证 → 徽章激励 → 继续练习。这是一个闭环。

⚠️ 但实际上：定级测试之后，只有代码审查和费曼能更新掌握度。如果用户只做竞技场，掌握度永远不变，闭环就断了。

定级测试做了什么

用户做5道题（读代码找bug + 手写小函数），系统算出一个总分。然后给全部12个知识点各写一条初始事件。

⚠️ 问题：12个知识点写的是同一条 correct 值（总分≥60就全部correct=true，否则全部false）。没有区分度——用户可能指针很强但排序很弱，定级看不出来。

定级之后，三轴经验值也按总分一刀切设置。这就是用户能力图谱的初始状态。

费曼检验的数据流

✅ 会写掌握度事件，数据流是通的。

❌ 但评分方式是纯关键词匹配，这就是你说的"鸡肋"：

• 用户写一段完全跑题的废话，只要碰巧包含"空列表""边界""因为""比如"这些词 → 可能拿"优秀"

• 用户用自己的话讲得完全正确，但没用预设同义词（比如用"空白"代替"空列表"）→ 会被判"待加强"

• 系统不会检测用户是否跑题——它只数关键词

• 没有追问机制——一次性提交、一次性评分、结束。真正的费曼教学法是互动的。

⚠️ 这意味着写入的 correct 标志可能不可信 → 污染了掌握度数据。

苏格拉底对话的数据流

❌ 这不是AI。是关键词路由 + 预设话术轮转。

• 用户说"我觉得指针很难" → 匹配到"指针" → 返回固定话术"你觉得p指向的内存被free之后..."

• 用户说"今天天气不错" → 没匹配到任何关键词 → 返回通用话术第N句

• 没有上下文记忆：上一轮说了什么完全不影响下一轮回复

• 不写掌握度事件：纯对话不产生任何掌握度数据

⚠️ 调研结论：Bastani et al. (PNAS 2025) 证明，无护栏的AI会损害学习（考试-17%），有护栏的AI导师能提升127%。但这里连AI都没有。

HLR 模型怎么工作

半衰期：每次答对，半衰期 ×1.8（记忆更持久）；每次答错，半衰期 ×0.5（记忆更快消退）。半衰期上限180天，下限0.2天。

回忆概率 p：当前时刻你还记得这个知识点的概率。p = 2^(-距上次答对天数 / 半衰期)。距离越远、半衰期越短，p 越低。

等级：不只是看 p，还要看答对次数和来源。

✅ 设计亮点：精通级要求「至少一次实战来源答对」——纯费曼永远到不了精通。这防止用户只靠嘴说就到顶。

✅ 事件源架构：p_l 不是直接存的，而是由事件序列重放计算。换算法（比如升级到FSRS）不需要改数据结构。

等级晋升条件

初识 → 熟悉：p ≥ 0.3（半衰期够长或刚答对过）

熟悉 → 熟练：p ≥ 0.6 且 答对 ≥ 3次

熟练 → 精通：p ≥ 0.8 且 答对 ≥ 4次 且 有两次间隔≥3天的答对 且 至少一次来自实战（审查/竞技场/认证）

⚠️ 精通要求"实战来源"，但竞技场不写掌握度事件。所以精通的实战来源只有代码审查和认证（认证还不写事件）。实际上只有代码审查算实战来源。

问题影响链

🔴 最严重：竞技场不写掌握度事件 → 调试轴4个知识点永远停滞 → 能力图谱上调试轴永远显示弱点 → 但推荐的主任务可能一直推调试模块 → 用户做了但掌握度不变 → 死循环。

🟡 次严重：费曼评分不准 → 写入的correct标志不可信 → p_l计算基于错误数据 → 仪表盘弱点推荐、主任务推荐、能力图谱显示都受影响。

🟡 苏格拉底导师不是AI → 用户体验差 → 导师模块形同虚设 → 智核消耗没有获得价值。

🟡 内容不足 → 用户很快做完所有内容 → 没有理由回来 → 留存率低。
