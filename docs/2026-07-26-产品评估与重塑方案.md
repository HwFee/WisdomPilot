## 一、现状诊断：为什么这个项目"没用"

> 以下诊断写于 2026-07-26，描述的是重塑前的旧系统。旧系统已于 2026-07-26~07-30
> 物理删除，本节作为历史记录保留，不再代表当前状态。当前架构见[第六章](#六实施进展截至-2026-07-30)。

### 1.1 价值主张的根基已经塌了

项目的核心卖点是"基于 GAI 的程序设计教学"——AI 生成知识点、AI 生成习题、AI 生成讲解。但在 2026 年，这个卖点存在致命问题：

- **学生绕过平台直接问 ChatGPT/Claude/豆包**，得到的是更强模型、更自由的交互、零成本。平台的 AI 生成内容质量反而更差（用户原话：挑战之路习题质量参差不齐、精进之路 AI 生成页面垃圾、知识点和习题垃圾）。
- **AI 最弱的能力被当成了核心产品**。让 AI 稳定生成"高质量、经过验证的教学内容"是行业公认难题；平台把最不可控的环节放在了用户体验的最中心。
- **刷题本身在被时代质疑**。"Why LeetCode is outdated in 2025"这类讨论已成主流——当 AI 能秒解算法题，"会做题"不再等于"会编程"。

### 1.2 功能体系的内在矛盾（代码探索实证）

| 矛盾 | 证据 |
|---|---|
| 三套并行成长体系，互不解释 | `users.xp` / `users.mastery_xp` / `users.total_xp`（死字段，无任何写入方）；三个排行榜接口三种排序 |
| 两套段位算法写同一字段 | `user_arena_profiles.tier`：分数阈值制（5 段）与星数制（7 段）并存，前后端常量定义不一致 |
| 三种 streak | `users.streak_days`（打卡）、`users.current_streak`（死字段）、`user_arena_profiles.current_streak`（连对数），同名不同义 |
| 孤儿页面 | `/leaderboard` 全站零入口；`MyCoursesGrid`、`KnowledgeMastery` 只被自己的测试引用 |
| 复制粘贴的流水页 | `/xp`、`/tier`、`/cores` 三页结构完全相同，各 106 行 |
| 两个"挑战"概念 | `/api/challenges`（任务挑战）与演武场 `challenge_sessions` 互不相干 |
| 并行进度系统 | 旧的 `chapter_progress` 百分比 vs 新的 BKT 掌握度四层聚合，数据双写 |
| 游戏化过载 | 仪表盘同一屏显示 3 次连续打卡天数 |

### 1.3 一句话总结现状

**这是一个用三套互相矛盾的游戏化外壳，包装了一个质量不可控的 AI 内容生成器的项目。** 它的每一项功能都是"以前那种结合优化"——把 Duolingo 的打卡、LeetCode 的刷题、段位系统的 PVP 拼在一起，但没有回答"2026 年学生为什么需要你而不是直接问 AI"。

## 二、市场调研摘要

> 调研于 2026-07-26 完成，趋势判断在重塑后仍然适用，本节保留原文。

### 2.1 国内竞品

| 平台 | 模式 | 对本项目的启示 |
|---|---|---|
| **头歌 Educoder** | 高校实训 B 端，60000+ 实训案例，课程绑定 | B 端课程市场已被占死，正面竞争无胜算 |
| **PTA（拼题A）** | 浙大出品，高校程序设计类课程作业/考试标配 | 同上，且免费/低价 |
| **洛谷** | OI 社区，题目质量靠社区评审沉淀 | 题库质量来自"人"，不是 AI |
| **牛客 / LeetCode** | 求职导向刷题 | 求职赛道饱和，且都在加 AI 助手 |

### 2.2 国际竞品

| 平台 | 模式 | 启示 |
|---|---|---|
| **Boot.dev** | 游戏化后端学习，订阅制，Trustpilot 4.3/5 | 游戏化可以作为留存手段，但必须建立在"课程质量极好"的前提下 |
| **Exercism** | 免费 + 人类导师代码反馈 | "真人反馈"是 AI 时代反而升值的东西 |
| **Codecademy / DataCamp** | 交互式课程 + AI 助手 | AI 是辅助位，不是内容生产主力 |
| **Duolingo** | 游戏化标杆 | streak 机制有效但被大量批评"为打卡而打卡"，学习效果存疑——本项目三套游戏化正是踩在这个坑里 |
| **Mimo / Sololearn** | 移动端碎片化学习 | 浅层市场，粘性差 |

### 2.3 关键趋势判断（2025–2026）

1. **"写代码"在贬值，"审代码"在升值。** AI 生成代码的成本趋近于零，行业对工程师的核心要求转向：读懂 AI 输出、发现其中的错误、调试、验证、改进。Microsoft Research、WEF《Shaping the Future of Learning 2026》均指向这一方向。
2. **评估诚信（assessment integrity）成为刚需。** 学生用 AI 代写作业是高校普遍痛点，"证明学生真的会了"的工具需求在上升。
3. **AI 导师的正确姿势是苏格拉底式追问**（Khanmigo 模式），不是直接生成讲义和答案。
4. **LeetCode 式刷题面试在松动**，但"无 AI 辅助的基本功"反而因此成为差异化能力。

### 2.4 市场空白（本项目的机会位）

**中文世界里，没有一个产品系统地训练"AI 时代的编程能力"——即阅读、审阅、调试、验证 AI 生成代码的能力，以及在无 AI 辅助下的基本功认证。**

- 头歌/PTA 训练"按要求写代码"（AI 时代最容易被替代的能力）
- 洛谷/LeetCode 训练"竞赛/面试题"
- 没有人训练"面对 AI 生成的一堆代码，快速判断对错、找出 bug、改进设计"

这恰好把本项目最大的劣势——"AI 生成内容质量不可控"——翻转成核心玩法：**生成"带缺陷的代码"远比生成"完美的教学内容"容易且可控**，因为缺陷本身就是目的。

## 三、重塑方案：从"AI 教你写代码"到"训练你在 AI 时代值钱的能力"

### 3.1 新价值主张

> **智码领航 = AI 时代的编程实战训练舱。**
> 不教你写代码（ChatGPT 就会），训练你**读懂、审查、调试、修复、超越** AI 写的代码。

### 3.2 四大训练模块

#### P0 · 代码审查室（Code Review Gym）— ✅ 已落地

- AI 生成一段"能跑但有坑"的代码（逻辑错误、边界遗漏、坏味道、性能陷阱），学生以 code review 形式找出问题。
- **为什么可行**：生成"有特定缺陷的代码"是 AI 的强项（缺陷可枚举、可注入、可自动验证），质量远好于"生成完美习题"。判分可以用注入的缺陷清单做确定性校验，不依赖模糊的 AI 评分。
- 难度梯度：改一个 bug → 找出所有 bug → 审查设计决策。
- 这是对"挑战之路"的直接替代：同一套 Monaco 编辑器 + Judge0 基础设施可以复用。

> **实施状态**：路由 `/review-gym`，后端端点 `GET /api/review-gym/session` +
> `POST /api/review-gym/submit`。判定逻辑 `judge_marks`（行号差 ≤1 且类型同即命中，
> `score = 命中率×70 + 精确率×30`）已实现为纯函数。未全中允许重做，只按"新增命中数"
> 结算防刷经验。种子数据 2 个审查关卡 + 5 个注入缺陷。注入缺陷表 `deck_injected_defects`
> 为服务端秘密，绝不下发前端。

#### P0 · 调试竞技场（Debug Arena）— ✅ 已落地

- 给一段"测试用例全挂"的程序 + 失败输出，限时修 bug。
- 调试是 AI 时代最保值的技能之一，也是学生真实痛点（看自己的代码 vs 看别人的代码）。
- 可保留排行榜，但只保留这一个竞技玩法，取代现在"段位+PVP+无限挑战"的臃肿组合。

> **实施状态**：路由 `/arena`，后端端点 `GET /api/arena/home` + `POST /api/arena/run`。
> 判定逻辑 `judge_arena_code` 当前为规则匹配版（字符串检测修复关键片段），代码注释
> 明确标注"后续换 Judge0"。ELO 评分系统 `deck_arena_ratings`（初始 1200），段位表
> 青铜(0)/白银(1200)/黄金(1500)/铂金II(1800)/钻石(2100)/王者(2400)。种子数据 1 个
> 竞技场挑战，按日轮换。

**审查与调试的区别**：审查是代码"能跑但有问题"，任务是通过阅读**找出**隐藏缺陷；
调试是代码"跑挂了"，任务是根据失败输出**修复**代码。前者训练审阅轴（不碰运行时），
后者训练调试轴（直接动手改）。

#### P1 · AI 苏格拉底导师（改造现有 AI 助手）— ✅ 已落地（脚本版）

- 现有 AI 提示/讲解改为追问式：不直接给答案，而是问"你觉得这段代码在输入为负数时会发生什么？"
- 智核消耗集中在这一个出口，货币体系瞬间有了明确意义。

> **实施状态**：路由 `/tutor`，后端端点 `GET /api/tutor/state` + `POST /api/tutor/message`
> + `POST /api/tutor/feynman` + `POST /api/tutor/feynman/check`。当前 `socratic_reply`
> 为脚本式关键词追问（注释标注"后续换 LLM"）。每问一次 -2 智核（`TUTOR_COST`），
> 余额不足返回 200 + 提示消息不扣费。费曼检验已并入导师（"考考我"模式），不设独立模块。

#### P1 · 费曼检验（Explain-it-back）— ✅ 已落地

- 学生学完一个知识点后，用自己的话向 AI 解释，AI 评估理解度并指出盲区。
- 直接对接已有的掌握度体系——用"能否讲清楚"替代"刷题正确率"作为掌握信号，评估更真实。

> **实施状态**：费曼评分纯函数在 `mastery.py` 中，评分 = 要点覆盖率 + 结构分（因果词 +
> 举例词），三档（优秀/良好/待加强）。费曼会话当前存内存 dict（`FEYNMAN_SESSIONS`），
> 注释标注"生产应换 Redis"。

#### P1 · 定级测试与主任务自适应（新手/老手分流）— ✅ 已落地

- **不分人群、只做任务分流**：四个训练模块对所有人开放，但「今日主任务」根据能力图谱自适应分发，界面上不出现任何"新手/老手"标签——用户只感到"系统推荐我练这个"。
- **5 分钟定级测试**（首次进入时）：读两段代码找 bug + 手写一个小函数，直接定出审阅/调试/实现三根能力轴的初始等级。同时解决能力图谱的冷启动问题。
- **新手期**（实现轴 < LV.3）：主任务从基本功认证、苏格拉底导师引导中分发；审查/调试模块标为"进阶"但不锁死。
- **老手期**：主任务从代码审查室、调试竞技场分发；基本功认证退为"已认证徽章墙"。

> **实施状态**：主任务分发 `build_main_task`（`router.py`）：未定级 → `null`；实现轴
> <LV.3 → 认证/费曼；否则取最低轴对应模块。带最多 2 个 `alternates` 备选。定级测试
> 试卷 ID = `placement`，含 MCQ + code 题。能力轴等级 = `1 + xp // 400`。

#### P2 · 基本功认证（No-AI Zone）— ✅ 已落地

- 定时的手写核心算法小测（关闭一切 AI 辅助），产出可分享的能力凭证。
- 呼应 assessment integrity 趋势，对个人是简历素材，对高校是防作弊工具。

> **实施状态**：路由 `/certification`，后端端点 `GET /api/certification/home` +
> `GET /api/certification/exam` + `POST /api/certification/submit`。能力凭证表
> `deck_certifications`（`verify_code` 全局唯一，可分享验证）。认证冷却 3 天
> （`CERT_COOLDOWN_DAYS`）。判定 `judge_cert_answer`：MCQ 字符串匹配 / code 题去空白后
> 含关键片段。题目答案表 `deck_cert_questions` 的 `answer_correct`/`answer_includes`
> 绝不下发。

### 3.3 统一成长体系：能力图谱替代三套货币

删掉 XP / 段位 / 智核三套并行叙事，改为**一张能力图谱**：

- **三根能力轴**：审阅（Review）、调试（Debug）、实现（Implement）。每根轴由掌握度驱动，`deck_ability_axes` 表记录 XP，等级 = `1 + xp // 400`。
- **智核保留但降级**：唯一变动途径 `change_cores`，余额地板 0，每笔写 `deck_core_transactions` 流水。导师每问 -2 智核，徽章解锁送智核（全解锁共 165 智核）。
- **排行榜只留一个**（调试竞技场 ELO），段位只服务于它。
- **打卡保留但收敛**：全站只在一个地方显示，不再奖励复杂倍率。

> **实施状态**：✅ 已落地。三套货币已收敛为智核单货币 + 能力图谱三轴。`deck_daily_activity`
> 记录每日活动，`deck_feed_events` 记录动态流（payload.segments 带 tone）。

### 3.4 徽章系统

> 新增于 2026-07-27，spec：`docs/superpowers/specs/2026-07-27-badge-system-design.md`

- 17 枚徽章（铜 7 / 银 7 / 金 3），含 3 枚隐藏徽章（`night-owl` / `perfect-score` / `comeback`）。
- 定义 + 判定引擎在 `backend/app/training/badges.py`（纯函数 `evaluate_and_award`，幂等）。
- 徽章定义在代码常量 `BADGES` 列表不入库；事实表只有 `deck_user_badges`。
- `collect_facts` 一次性聚合事实，四个提交端点 commit 前统一评估，响应带 `new_badges`。
- 认证页徽章墙走 `/certification/home` 的 `badges` 字段，隐藏徽章在解锁前脱敏。
- 解锁仪式动画 `BadgeUnlockCelebration`（全屏遮罩、stroke 描绘、CountUp、像素粒子）。

### 3.5 一生一策：个性化训练路径

> 新增于 2026-07-30。设计依据：全栈代码审查（`mastery.py` / `service.py` / `router.py`）+
> 产品差异化分析。本章描述的是**跨模块的个性化设计原则**，不绑定单一功能。

#### 设计理念

训练舱的差异化护城河不只是"训练 AI 时代编程能力"，还在于**每个用户看到的训练内容、
推荐节奏、追问方向都不一样**--即"一生一策"。市面上刷题平台给所有人推同一道"今日题"，
课程平台给所有人走同一条章节线性路径。训练舱的 HLR 记忆模型 + 三轴能力图谱 + 事件溯源
天然支持 per-user 个性化，但**数据基础设施 ≠ 用户体感**--如果用户看到的推荐卡片和别人的
一模一样，个性化就是隐形的。

目标：让用户从第一天起就建立"系统在为我个人定制路径"的认知，并且这个认知是真实的、
有数据支撑的，不是营销话术。

#### 现有基础（已落地）

训练舱的个性化引擎已经完整运转，以下是已有能力及其代码位置：

| 能力 | 代码位置 | 个性化机制 |
|---|---|---|
| HLR 记忆模型 | `mastery.py: half_life_days` / `recall_probability` | 每人每个知识点的半衰期独立演化，遗忘曲线因人而异 |
| 四级掌握状态机 | `mastery.py: mastery_level` | 初识/熟悉/熟练/精通，精通要求实战来源 + 间隔重复，路径不可速通 |
| 三轴能力图谱 | `service.py: get_axes` | 审阅/调试/实现三轴独立计 XP，每人能力"形状"不同 |
| 主任务分发 | `router.py: build_main_task` | 按最低轴推荐今日任务，未定级返回 null 引导定级 |
| 弱点检测 | `router.py: _weakest_kp_names` | p_l 最低的知识点优先推费曼检验 |
| 定级测试冷启动 | `service.py: has_placement` | 5 分钟测出三轴初始等级，解决冷启动 |
| 复盘队列 | `router.py: _build_review_queue` | 按个人错题/失败项/弱知识点聚合，每人队列不同 |
| 趋势追踪 | `mastery.py: compute_trend` | 每个知识点 7 天趋势独立计算（up/flat/down） |

**结论**：引擎已经就绪，缺的是**把引擎的运转过程暴露给用户**。

#### 三层落地策略

##### 第一层：让个性化可见（呈现层，不改算法）

目标：用户打开 dashboard 第一眼就意识到"这个页面是给我定制的"。

| 编号 | 改动 | 说明 | 涉及代码 |
|---|---|---|---|
| P-01 | 主任务卡片加推荐理由 | `main_task` 增加 `reason` 字段，说明"为什么推荐这个给你"--引用用户具体的能力轴等级和弱点知识点。例："你的「调试」轴是三轴最低（LV.2），这一关专攻「二分查找边界」" | `router.py: build_main_task` + 前端卡片组件 + `types.ts` |
| P-02 | Dashboard 能力指纹可视化 | 用三轴等级 + 13 个知识点 p_l 做一个极简雷达图/三轴条形图，放在 dashboard 顶部。两个人同时打开首页，看到的形状完全不同 | 前端 dashboard 组件，数据已有（`ability_map.axes` + `weak_points`） |
| P-03 | 定级测试结果仪式页 | 定级完成后展示"入舱画像"：三轴初始等级 + 专属路径说明。文案如"系统为你生成了专属训练路径，与全站多数用户的起点不同" | 前端新增结果页组件 |
| P-04 | 弱点区域标注个性化来源 | Dashboard 的 `weak_points` 区域每个弱点旁标注"为什么出现在这里"：来自哪次审查漏报/竞技场失败 | `router.py: get_dashboard` 弱点查询扩展 |

##### 第二层：让个性化动起来（调度层，改内容选择逻辑）

目标：不同用户在同一时间点看到**不同的训练内容**，而不只是不同的推荐文案。

| 编号 | 改动 | 说明 | 涉及代码 |
|---|---|---|---|

#### 设计约束

1. **不新增表**：所有个性化逻辑基于已有的 `deck_mastery_events` / `deck_user_mastery` /
   `deck_ability_axes` 等表，不增加新的数据模型。P-06 间隔重复调度只是对现有 p_l 的
   阈值过滤，P-09 时间线基于已有的 `deck_feed_events`。
2. **不改契约层架构**：新增字段（如 `main_task.reason`）走现有 `types.ts` +
   snake_case 契约，不改 `client.ts` 的 mock/真后端切换机制。
3. **不过度承诺**：P-03/P-11 的文案要说"基于你的能力数据推荐"，不说"AI 为你生成专属
   课程"。个性化是基于数据的规则匹配，不是 AI 生成--避免重蹈旧系统"AI 生成内容质量
   不可控"的覆辙。
4. **尊重隐私**：P-11 路径指纹只暴露能力分布的粗粒度信息（轴等级），不暴露具体弱点
   知识点，防止被用于逆向推测用户水平。

## 五、风险评估

### 5.1 内容质量风险（用户已指出，最高优先级）

- **现状**：~~挑战之路习题质量参差、精进之路 AI 页面垃圾、知识点/习题垃圾。~~ 已通过重塑解决：内容主力从"生成"转向"注入缺陷"，缺陷可枚举、可注入、可自动验证。
- **剩余风险**：种子数据量小（2 个审查关卡 + 1 个竞技场挑战 + 2 套试卷 11 题），需要持续扩充题库。
- **对策**：① 内容主力从"生成"转向"注入缺陷"（P0 功能天然规避此风险）——✅ 已落地；② 必须保留的生成内容全部过 Judge0 确定性验证 + 抽样人工评审——⏳ Judge0 尚未接入；③ 建立题目质量分——⏳ 未实现。

### 5.4 数据迁移风险

- 审查关卡：当前 2 个（+ 5 个注入缺陷）→ 目标 30+
- 竞技场挑战：当前 1 个 → 目标 20+
- 认证试卷：当前 2 套（cert-pointer + placement，11 题）→ 目标 5+ 套
- 知识点：当前 13 个（review 4 / debug 4 / implement 5）→ 按需扩充

### 7.3 后续路线

1. **Judge0 接入**：调试竞技场 + 认证 code 题从规则匹配升级为真执行判题。需要降级方案（本地 runner 或缓存）。
2. **LLM 导师接入**：苏格拉底导师从脚本式升级为 LLM 对话。需要 AI API 成本核算 + 智核定价调整。
3. **题库扩充**：审查关卡 + 竞技场挑战 + 认证试卷持续新增。
4. **AI 生成弱点变式题**：基于 `deck_mastery_events` 事件流分析个人弱点，按需生成变式题，必须过 Judge0 验证才能入库。
5. **费曼会话持久化**：从内存 dict 迁移到 Redis，支持跨会话。
6. **题目质量反馈**：一键"这题有问题吗"反馈收集。
7. **一生一策个性化路径**（详见 [§3.5](#35-一生一策个性化训练路径)）：分三层落地--
   - **呈现层**（P0-P1）：主任务推荐理由 `reason` 字段、Dashboard 能力指纹可视化、定级仪式页、弱点来源标注。
   - **调度层**（P1-P2）：审查关卡按弱点匹配、间隔重复调度（p_l 阈值过滤）、导师追问注入用户上下文、难度自适应。
   - **叙事层**（P2-P3）：训练档案路径时间线、能力演化对比、路径唯一性标识。
   - 核心原则：不新增表、不改契约架构、基于已有 HLR + 三轴数据、不过度承诺。
