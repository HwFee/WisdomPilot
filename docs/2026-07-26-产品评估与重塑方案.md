# 智码领航 · 产品评估与重塑方案

> 日期：2026-07-26
> 范围：产品定位、市场竞争、功能增删、风险评估
> 依据：全栈代码探索（前后端功能盘点）+ 公开市场调研（tavily 检索，来源见文末）

---

## 一、现状诊断：为什么这个项目"没用"

### 1.1 价值主张的根基已经塌了

项目的核心卖点是"基于 GAI 的程序设计教学"——AI 生成知识点、AI 生成习题、AI 生成讲解。但在 2026 年，这个卖点存在致命问题：

- **学生绕过平台直接问 ChatGPT/Claude/豆包**，得到的是更强模型、更自由的交互、零成本。平台的 AI 生成内容质量反而更差（用户原话：挑战之路习题质量参差不齐、精进之路 AI 生成页面垃圾、知识点和习题垃圾）。
- **AI 最弱的能力被当成了核心产品**。让 AI 稳定生成"高质量、经过验证的教学内容"是行业公认难题；平台把最不可控的环节放在了用户体验的最中心。
- **刷题本身在被时代质疑**。"Why LeetCode is outdated in 2025"这类讨论已成主流——当 AI 能秒解算法题，"会做题"不再等于"会编程"。

### 1.2 功能体系的内在矛盾（代码探索实证）

| 矛盾 | 证据 |
|---|---|
| 三套并行成长体系，互不解释 | `users.xp` / `users.mastery_xp` / `users.total_xp`（死字段，无任何写入方）；三个排行榜接口三种排序 |
| 两套段位算法写同一字段 | `user_arena_profiles.tier`：分数阈值制（5 段）与星数制（7 段）并存，前后端常量定义不一致 |
| 三种 streak | `users.streak_days`（打卡）、`users.current_streak`（死字段）、`user_arena_profiles.current_streak`（连对数），同名不同义 |
| 孤儿页面 | `/leaderboard` 全站零入口；`MyCoursesGrid`、`KnowledgeMastery` 只被自己的测试引用 |
| 复制粘贴的流水页 | `/xp`、`/tier`、`/cores` 三页结构完全相同，各 106 行 |
| 两个"挑战"概念 | `/api/challenges`（任务挑战）与演武场 `challenge_sessions` 互不相干 |
| 并行进度系统 | 旧的 `chapter_progress` 百分比 vs 新的 BKT 掌握度四层聚合，数据双写 |
| 游戏化过载 | 仪表盘同一屏显示 3 次连续打卡天数 |

### 1.3 一句话总结现状

**这是一个用三套互相矛盾的游戏化外壳，包装了一个质量不可控的 AI 内容生成器的项目。** 它的每一项功能都是"以前那种结合优化"——把 Duolingo 的打卡、LeetCode 的刷题、段位系统的 PVP 拼在一起，但没有回答"2026 年学生为什么需要你而不是直接问 AI"。

## 二、市场调研摘要

### 2.1 国内竞品

| 平台 | 模式 | 对本项目的启示 |
|---|---|---|
| **头歌 Educoder** | 高校实训 B 端，60000+ 实训案例，课程绑定 | B 端课程市场已被占死，正面竞争无胜算 |
| **PTA（拼题A）** | 浙大出品，高校程序设计类课程作业/考试标配 | 同上，且免费/低价 |
| **洛谷** | OI 社区，题目质量靠社区评审沉淀 | 题库质量来自"人"，不是 AI |
| **牛客 / LeetCode** | 求职导向刷题 | 求职赛道饱和，且都在加 AI 助手 |

### 2.2 国际竞品

| 平台 | 模式 | 启示 |
|---|---|---|
| **Boot.dev** | 游戏化后端学习，订阅制，Trustpilot 4.3/5 | 游戏化可以作为留存手段，但必须建立在"课程质量极好"的前提下 |
| **Exercism** | 免费 + 人类导师代码反馈 | "真人反馈"是 AI 时代反而升值的东西 |
| **Codecademy / DataCamp** | 交互式课程 + AI 助手 | AI 是辅助位，不是内容生产主力 |
| **Duolingo** | 游戏化标杆 | streak 机制有效但被大量批评"为打卡而打卡"，学习效果存疑——本项目三套游戏化正是踩在这个坑里 |
| **Mimo / Sololearn** | 移动端碎片化学习 | 浅层市场，粘性差 |

### 2.3 关键趋势判断（2025–2026）

1. **"写代码"在贬值，"审代码"在升值。** AI 生成代码的成本趋近于零，行业对工程师的核心要求转向：读懂 AI 输出、发现其中的错误、调试、验证、改进。Microsoft Research、WEF《Shaping the Future of Learning 2026》均指向这一方向。
2. **评估诚信（assessment integrity）成为刚需。** 学生用 AI 代写作业是高校普遍痛点，"证明学生真的会了"的工具需求在上升。
3. **AI 导师的正确姿势是苏格拉底式追问**（Khanmigo 模式），不是直接生成讲义和答案。
4. **LeetCode 式刷题面试在松动**，但"无 AI 辅助的基本功"反而因此成为差异化能力。

### 2.4 市场空白（本项目的机会位）

**中文世界里，没有一个产品系统地训练"AI 时代的编程能力"——即阅读、审阅、调试、验证 AI 生成代码的能力，以及在无 AI 辅助下的基本功认证。**

- 头歌/PTA 训练"按要求写代码"（AI 时代最容易被替代的能力）
- 洛谷/LeetCode 训练"竞赛/面试题"
- 没有人训练"面对 AI 生成的一堆代码，快速判断对错、找出 bug、改进设计"

这恰好把本项目最大的劣势——"AI 生成内容质量不可控"——翻转成核心玩法：**生成"带缺陷的代码"远比生成"完美的教学内容"容易且可控**，因为缺陷本身就是目的。

## 三、重塑方案：从"AI 教你写代码"到"训练你在 AI 时代值钱的能力"

### 3.1 新价值主张

> **智码领航 = AI 时代的编程实战训练舱。**
> 不教你写代码（ChatGPT 就会），训练你**读懂、审查、调试、修复、超越** AI 写的代码。

### 3.2 新功能（按推荐优先级）

#### P0 · 代码审查室（Code Review Gym）— 核心新玩法

- AI 生成一段"能跑但有坑"的代码（逻辑错误、边界遗漏、坏味道、性能陷阱），学生以 code review 形式找出问题。
- **为什么可行**：生成"有特定缺陷的代码"是 AI 的强项（缺陷可枚举、可注入、可自动验证），质量远好于"生成完美习题"。判分可以用注入的缺陷清单做确定性校验，不依赖模糊的 AI 评分。
- 难度梯度：改一个 bug → 找出所有 bug → 审查设计决策。
- 这是对"挑战之路"的直接替代：同一套 Monaco 编辑器 + Judge0 基础设施可以复用。

#### P0 · 调试竞技场（Debug Arena）

- 给一段"测试用例全挂"的程序 + 失败输出，限时修 bug。
- 调试是 AI 时代最保值的技能之一，也是学生真实痛点（看自己的代码 vs 看别人的代码）。
- 可保留排行榜，但只保留这一个竞技玩法，取代现在"段位+PVP+无限挑战"的臃肿组合。

#### P1 · AI 苏格拉底导师（改造现有 AI 助手）

- 现有 AI 提示/讲解改为追问式：不直接给答案，而是问"你觉得这段代码在输入为负数时会发生什么？"
- 智核（cores）消耗集中在这一个出口，货币体系瞬间有了明确意义。

#### P1 · 费曼检验（Explain-it-back）

- 学生学完一个知识点后，用自己的话向 AI 解释，AI 评估理解度并指出盲区。
- 直接对接已有的 BKT 知识点掌握度体系——用"能否讲清楚"替代"刷题正确率"作为掌握信号，评估更真实。

#### P1 · 定级测试与主任务自适应（新手/老手分流）

- **不分人群、只做任务分流**：四个训练模块对所有人开放，但「今日主任务」根据能力图谱自适应分发，界面上不出现任何"新手/老手"标签——用户只感到"系统推荐我练这个"。
- **5 分钟定级测试**（首次进入时）：读两段代码找 bug + 手写一个小函数，直接定出审阅/调试/实现三根能力轴的初始等级。同时解决能力图谱的冷启动问题（没有历史数据时 BKT 无法给出有意义的掌握度）。
- **新手期**（实现轴 < LV.3）：主任务从基本功认证、苏格拉底导师引导中分发；审查/调试模块标为"进阶"但不锁死，避免零基础用户被找茬任务劝退。
- **老手期**：主任务从代码审查室、调试竞技场分发；基本功认证退为"已认证徽章墙"，作为背书工具存在。

#### P2 · 基本功认证（No-AI Zone）

- 定时的手写核心算法小测（关闭一切 AI 辅助），产出可分享的能力凭证。
- 呼应 assessment integrity 趋势，对个人是简历素材，对高校是防作弊工具（未来 B 端故事的种子）。

### 3.3 统一成长体系：能力图谱替代三套货币

删掉 XP / 段位 / 智核三套并行叙事，改为**一张能力图谱**：

- **三根能力轴**：审阅（Review）、调试（Debug）、实现（Implement）。每根轴由 BKT 掌握度驱动，就是现有 `knowledge_point_mastery` 的重新分组，不需要新发明算法。
- **智核保留但降级**：它只是 AI 导师的"提问次数"余额，不再是一种"成长体系"。
- **排行榜只留一个**（调试竞技场），段位只服务于它。
- **打卡保留但收敛**：全站只在一个地方显示，不再奖励复杂倍率。

## 四、删减清单

### 4.1 立即删除（死代码/死字段，纯收益）

- `users.total_xp`（无写入方）、`users.current_streak`（死字段）
- 前端孤儿组件 `MyCoursesGrid.tsx`、`KnowledgeMastery.tsx`
- 前端零调用的 API 封装：`getAchievements*`、`generateExercises`、`submitExercise`、`verifyExercise`、`getExerciseRecommendations` 等
- `/api/cores/test/earn|spend`、`/api/test/*` 沙箱（上线前必须关，经济系统后门）
- 旧进度系统 `chapter_progress` / `section_progress`（数据迁移到 BKT 体系后删表）
- `users.weak_points` JSON 列（与 `user_weak_points` 表重复，保留表）

### 4.2 合并收敛

- `users.xp` + `users.mastery_xp` → 一个 XP 字段 + 一本账
- `/xp`、`/tier`、`/cores` 三个流水页 → 一个"成长档案"页（三个 tab）
- `/leaderboard` 孤儿页 → 并入成长档案或给它导航入口
- `/api/challenges`（任务挑战）与演武场 challenge → 二选一，建议删任务挑战（又一个没人知道入口的平行系统）
- 段位两套算法 → 只留星数制（`tier_config.py`），删分数阈值映射
- 仪表盘 3 次打卡显示 → 1 次

### 4.3 重做而非删除

- **挑战之路** → 重做为调试竞技场（题库改为"注入缺陷的代码"，复用 Monaco + Judge0）
- **精进之路** → 砍掉 AI 生成讲义页面，保留 BKT 掌握度内核，内容来源改为：人工精编知识卡 + AI 苏格拉底导师 + 费曼检验
- **AI 生成习题** → 不再作为内容主力，转为按需生成"针对个人弱点的变式题"，且必须过 Judge0 自动验证才能入库

## 五、风险评估

### 5.1 内容质量风险（用户已指出，最高优先级）

- **现状**：挑战之路习题质量参差、精进之路 AI 页面垃圾、知识点/习题垃圾。
- **根因**：把 AI 生成放在"教学内容"这个质量最敏感的位置，且无人工/自动校验环节。
- **对策**：① 内容主力从"生成"转向"注入缺陷"（P0 功能天然规避此风险）；② 必须保留的生成内容全部过 Judge0 确定性验证 + 抽样人工评审；③ 建立题目质量分（做完自动收集"这题有问题吗"一键反馈）。

### 5.2 作弊/诚信风险

- 学生把题目粘贴给 ChatGPT 即可通关，一切"做题正确率"数据失真，BKT 掌握度被污染。
- **对策**：新玩法（审阅、调试、费曼解释）本身对"直接问 AI"脱敏——让 AI 审 AI 的代码可以，但这恰恰是我们要训练的能力，平台可以检测"学生是否真的理解"（追问环节）。基本功认证采用限时+无 AI 环境。

### 5.3 技术风险

- Judge0 单点依赖：判题服务挂则核心玩法全停 → 需要降级方案（本地 runner 或缓存判题结果）。
- BKT 参数质量：现有掌握度数值未必可信，能力图谱上线前需要用真实答题数据回测校准。
- AI API 成本：苏格拉底导师 + 费曼检验比"一次生成讲义"调用更频繁 → 智核定价需要重新核算，防止入不敷出。

### 5.4 数据迁移风险

- 删字段、并表、统一 XP/段位涉及存量数据 → 每个变更必须有迁移脚本 + 回滚脚本（项目 AGENTS.md Rule 5 已要求），先在副本库演练。

### 5.5 市场风险

- B 端（高校课程）被头歌/PTA 绑定极深，短期不要正面进攻；C 端获客难，编程学习付费意愿低。
- **定位纪律**：不做求职刷题（LeetCode/牛客）、不做课程作业平台（头歌）、不做竞赛社区（洛谷）。只守"AI 时代编程实战能力"这一个生态位，先小而尖。
- 差异化窗口期有限：这个方向大模型厂商和头部平台都可能做，执行速度是关键。

### 5.6 范围风险（最大的人为风险）

- 本文档的完整重塑是大工程。**强烈建议按 MVP 切分**：
  1. **第一阶段（止血）**：执行 4.1 全部删除项 + 4.2 合并项，把三套体系收敛成一套。纯工程，无产品风险。
  2. **第二阶段（验证）**：只做 P0 代码审查室一个玩法，小流量验证留存。
  3. **第三阶段（扩展）**：P1/P2 按验证结果决定。
- 不要试图一次性做完，这个项目的历史教训（功能堆砌、无人维护的平行系统）正是范围失控的结果。
